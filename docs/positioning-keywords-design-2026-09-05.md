# RankCues：定位、关键词与第二版视觉方向

日期：2026-09-05。依据：当前产品代码、公开竞品页面、公开用户讨论。以下人群与优先级是待验证的商业假设，不是访谈结果或搜索量统计。

## 1. 产品定位

建议定位：为独立 SEO 顾问和小型 SEO 团队提供基于 Search Console 的诊断与行动工作区，把多个客户网站的数据变化、证据、下一步任务和可审核报告连接起来。

首要用户：亲自负责多个客户网站的 SEO 顾问、工作室创始人、SEO 负责人。优先招募管理约 3–20 个网站的操作者验证；这只是招募分组，不是产品限额。购买者通常是顾问本人或团队负责人，实际操作者是 SEO 专员；客户是报告阅读者。

次要用户：管理多个内容站、联盟站的运营者。他们更关心页面衰退与更新优先级，未必需要客户汇报，应单独验证。

暂不作为主攻人群：只想一键涨排名的小商家；要求成熟白标交付、复杂角色和客户门户的大机构；要求实时本地排名或 AI 搜索曝光追踪的用户。

| 痛点 | 证据性质 | 产品应答 | 验证任务 |

| 流量下降时不知道先查哪页、哪个查询 | 产品工作流推断；竞品也强调分析与诊断 | 从异常进入页面/查询，区分观察、相关与假设 | 给一个真实下降案例，让用户找出下一步 |
| 客户不读仪表盘，仍要求解释和报告 | 公开用户自述 | 可审核的变化说明和行动摘要 | 让用户对比现有报告和样例，指出可直接使用的内容 |

首页大纲：

价格页大纲：
1. 品牌价格/准入标题；明确当前为邀请制内测。
2. 一个真实的内测准入卡片，不虚构美元金额或免费套餐。

5. 样例和受邀登录入口。

EEAT：明确样例身份；仅承诺代码支持的能力；不编造数据、证言、效果或因果关系；公开权限与产品阶段；后续真实案例需经授权并写明方法、时间范围、数据来源和局限。

## 5. 建议的首月验证顺序

- 第 1 周：上线本地审核后的首页/价格页，招募 5 位匹配顾问做首次使用观察；记录理解产品所需解释、连接障碍及首次报告是否有可执行结论。
- 第 2 周：优化 automated-seo-reports 现有页，制作 GSC 商业页面；每个页面独立查询当前 Google 前十并重新拟大纲。
- 第 3 周：更新 anomaly、CTR decline、change tracking 三篇现有内容，串联到样例及相关功能页。
- 第 4 周：得到授权后发布一份匿名真实案例与实用报告模板。观察搜索曝光/查询匹配、样例互动、受邀用户连接成功率与首次报告完成率。

衡量链路：访问 → 看样例 → 切到行动/摘要 → 已受邀用户登录 → 数据同步成功 → 首次报告生成并查看。应区分访问者与受邀用户漏斗，避免把邀请制摩擦误判为视觉问题。上述埋点是后续实施建议，本轮没有声称已部署分析事件。
