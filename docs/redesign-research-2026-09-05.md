# RankCues 新用户体验改版

研究日期：2026-09-05。目标：让新用户理解价值，并完成首次使用。

## 研究范围与证据边界

检查了首页、共享导航、登录页、工作台总览、网站接入和报告生成代码，以及现有产品定位文档。目标用户沿用项目已定义的管理多个客户网站的小型 SEO 团队。

这是公开资料研究与界面启发式审查，没有进行真实客户访谈，也没有取得本站转化漏斗数据。以下优先级是设计判断，不是用户发生率或统计结论。

按首页主关键词 `SEO reporting software for agencies` 检索并阅读十个结果页。尝试通过 Google 浏览器页面核验自然排名，但浏览器控制连续超时；以下是搜索工具返回的前十个网页样本，不能声称是经核验的 Google 固定前十名。未改写其他公开 SEO 落地页的正文，避免在没有逐页关键词研究的情况下扩大内容范围。登录与工作台不索引，以任务完成为目标。

## 痛点 → 现状 → 设计响应

| 痛点 | 证据与可信程度 | 本站问题 | 改版响应 |
|---|---|---|---|
| 客户看不懂报告，需要解释与行动 | [SEO 社区讨论](https://www.reddit.com/r/SEO/comments/148n074/seo_site_analysis_on_behalf_of_prospective_clients/) 中的从业者反馈；定性线索 | 首页先讲 evidence rail、confidence，未先解释交付物 | 直接展示变化、来源、下一步与客户摘要 |
| 反复导出、拼数据、制作汇报耗时 | 多个供应商页面共同定位；属于市场需求信号 | 五步工作流很抽象，缺少可体验的产出 | 三个可切换示例视图，接入→分析→审核的短路径 |
| 新用户不知道先点哪个功能 | 本站审查：12 个入口平铺 | 报告排在关键词、流量、外链、推广后面 | 每日工作、数据分析、管理设置分组，报告前置 |
| 没有数据时不知道该怎么办 | 本站审查：总览只有空白提示与连接按钮 | 没有准备清单、预期结果和备选路径 | 新手引导说明账号、网站同步、首份报告；可回看示例 |
| 不愿在理解价值前授权 Google | 待访谈验证的假设，竞争页面普遍解释只读权限 | 主要 CTA 直接进入授权门槛 | 无登录示例，登录前说明权限与自动导入行为 |
| 接入步骤过多 | 本站代码：GA4、快照、报告混在五个必做步骤里 | 用户可能误以为所有集成都必须完成 | 必需步骤与可选增强分开，保持原有后端流程 |
| 担心 AI 编造原因 | 本站能力边界与合理风险假设 | 示例写出没有解释依据的 82% 置信度 | 移除装饰性百分比；明确观察不证明因果，建议需要核查 |
| 注册途中被邀请制挡住 | 已核验登录与 contact 页面 | “Open private beta”未解释资格 | 提前写明受邀登录，公开示例向所有人开放 |

## 内容大纲（编码前确定）

1. 导航：产品流程、报告功能、资源、价格；示例与受邀登录路径。
2. 首屏：SEO reporting software for agencies 分类 + 清楚的结果承诺。
3. 可交互示例：变化 / 下一步 / 客户摘要；持续显示示例数据标识。
4. 数据来源：Search Console、可选 GA4、页面快照，各自负责什么。
5. 价值：少切换工具、知道该检查什么、用客户语言解释。
6. 三步首用：连接账号与导入属性、同步一个网站、生成并审核报告。
7. FAQ：权限、GA4 是否必需、AI 是否证明因果、是否能注册、能否自动修改网站。
8. 底部行动：受邀用户开始，其他用户查看示例；说明内测状态。

## 视觉与信息架构

暖白背景、墨绿色行动按钮、编辑式 Newsreader 标题、Manrope 界面字与等宽数据。首屏采用左右布局，右侧以真实 HTML 构建可阅读的报告工作区。减少光晕、阴影与装饰性微小文本；手机显示可展开导航。

后台保留所有路由与真实数据，先通过共享外壳、导航分组、总览引导和连接页层级降低首次使用负担。原有报告生成仍走既有任务队列，不在演示区触发真实接口。

## E-E-A-T 与产品事实

- 不编造客户评价、用户数量、节省时间、收入提升、排名保证或认证。
- 演示中所有网站和数字均为虚构示例；不混入工作台。
- 只读范围专指 Google 数据权限，不能扩大成所有执行功能都只读。
- 网站修改功能仍须通过现有任务审核和执行路径。
- 不承诺白标 PDF、自动向客户发送或公开注册，当前代码未提供这些完整能力。
- 保留资源、关于、价格与隐私入口，解释信息来源和不确定性。

## 后续用户验证方案（尚未执行）

邀请 5 位符合目标用户的小型代理商操作者，记录三个任务：30 秒解释产品用途；无提示找到报告示例；用测试网站完成首次报告。观察迷路点，不提示点击路径。

访谈问题：最近一次汇报最耗时的环节是什么？客户最常追问什么？连接 Google 前需要知道什么？哪一项报告结论会让你不敢发给客户？

建议漏斗：主页→示例交互→受邀登录→网站同步成功→报告生成成功→查看报告。把“报告生成成功”作为首用完成指标；同时记录授权失败、无网站权限、数据同步失败。需明确授权再添加分析追踪，不在本次改版中收集个人信息。

## 本次实现与验证结果

已实现：新版首页与公开交互报告示例；共享官网导航与手机菜单；登录页与邀请制说明；后台导航分组；中英西三语首用引导与下一步提示；连接页三个主要步骤、可选集成和折叠诊断。

验证记录：

- `npm run build`：最终代码通过生产构建与 TypeScript 检查。
- `npm run lint`：通过；最后的小幅修改另对全部变更 TS/TSX 文件运行 ESLint，也通过。
- `npm test`：6 个测试文件、65 项现有测试通过；没有将这些单元测试声称为 UI 或授权端到端测试。
- Chrome 实际检查桌面首页、390px 手机首页与登录页；报告三个视图、手机菜单、锚点导航与 FAQ 展开可操作。
- 中文工作台在独立组件预览中检查了桌面导航和新手引导，没有绕过正式路由认证或接入虚构工作台数据。
- HTTP 检查：首页、登录页、邀请错误状态、报告功能页、价格页与变化跟踪文章均为 200；未登录访问 `/app/overview`、`/app/connect` 为 307，保留正确的 returnTo。
- 本地开发存在原有 CSP 限制 React 调试 eval 的提示；生产构建成功。本次未放宽 CSP。
- 本地预览使用回环地址的 Hyperdrive 测试连接配置，未连接生产数据库。未执行真实 Google 授权、真实数据同步、真实报告生成或网站部署。
